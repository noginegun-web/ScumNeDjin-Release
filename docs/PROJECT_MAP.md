# Карта исходного дерева

Этот документ помогает ориентироваться в публичной developer-версии
ScumNeDjin. Он описывает назначение каталогов, а не является инструкцией по
установке на конкретный сервер.

## Компоненты

| Путь | Ответственность | Что не должно находиться здесь |
| --- | --- | --- |
| `src/native` | Нативный `version.dll`, локальный HTTP/API-слой, конфигурационный ввод-вывод и bridge-клиент. | Ключи, snapshots, базы, логи и собранные DLL. |
| `src/native/tests` | Небольшие воспроизводимые CTest-проверки нативного кода. | Зависимости от рабочего сервера. |
| `src/ue4ss_cppmods/ScumNedjinManagedBridgeMod` | Исходник необязательного C++ entry point для UE4SS. | `UE4SS.lib`, game headers и готовые binaries. |
| `src/ue4ss_cppmods/SCUMTraderManager` | Исходник экспериментального C++-модуля; его границы и совместимость нужно проверять отдельно от базового моста. | Привязки к частным окружениям и результаты runtime-экспериментов. |
| `ue4ss/Mods/ScumNeDjinBridge` | Серверная Lua-логика UE4SS и модульные маршруты. | Глобальные периодические object scans как способ поиска игроков. |
| `ue4ss/ScumNeDjin/configs` | Безопасные конфигурационные шаблоны. | Рабочие адреса, пароли, токены и личные данные. |
| `ue4ss/ScumNeDjin/web` | Статическая панель, которую раздаёт нативный слой. | Компилированные frontend-бандлы из частного окружения. |
| `scripts` | Проверки публичной поставки и вспомогательные build-gates. | Инструменты, способные менять live-сервер без явного действия оператора. |

## Границы ответственности

```text
panel view
    │  отображает подтверждённое состояние и отправляет ограниченный запрос
    ▼
native HTTP/API layer
    │  валидирует маршрут и передаёт его мосту
    ▼
UE4SS bridge
    │  планирует игровую работу только на подходящем GameThread пути
    ▼
SCUM runtime
```

Панель не является источником истины о живом игроке или результате игровой
операции. Для автоматических модулей нужен отдельный журналируемый результат
модуля и соблюдение [правил player-aware automation](PLAYER_AUTOMATION_SAFETY.md).

## Порядок локальной проверки

1. Запустите команды из [BUILDING.md](../BUILDING.md) для нативного кода.
2. Соберите каждый нужный C++-модуль отдельно с совместимой локальной
   `UE4SS.lib` по [UE4SS_CPPMOD_BUILDING.md](UE4SS_CPPMOD_BUILDING.md).
3. Выполните `node --check ue4ss/ScumNeDjin/web/app.js`.
4. Выполните `scripts/Test-PublicTree.ps1` перед коммитом, PR или упаковкой.

Проверка исходного дерева не доказывает, что конкретная игровая команда
сработала на живом сервере. Для этого нужны совместимая версия SCUM/UE4SS,
резервная копия, runtime evidence и видимый результат на контролируемом
сервере.

## Где вносить изменения

- Поведение в браузере — `ue4ss/ScumNeDjin/web`.
- Ограничения HTTP/API и безопасные defaults — `src/native` и шаблоны
  `ue4ss/ScumNeDjin/configs`.
- Игровая логика — `ue4ss/Mods/ScumNeDjinBridge` либо отдельный C++-модуль.
- Публичные правила, сборка и release-контракт — root-документы, `docs` и
  `scripts`.

Не смешивайте эти уровни в одном большом изменении. Для каждого изменения
покажите маршрут, ограничения, журналирование и отдельную проверку.
