> Открытая панель управления и безопасный runtime-мост для разработчиков
> выделенных серверов SCUM.

**ScumNeDjin** — канонический открытый проект, который соединяет локальную
веб-панель, нативный HTTP/API-слой и UE4SS-мост. Его задача — дать
разработчикам воспроизводимую базу для собственных серверных модулей, не
публикуя чьи-либо частные окружения или игровые материалы.

Оригинальный автор и сопровождающий проекта —
[`noginegun-web`](https://github.com/noginegun-web). Публичные производные
версии приветствуются по правилам [AGPL](LICENSE): сохраняйте авторство и
уведомления, указывайте связь с ScumNeDjin и используйте собственное имя для
изменённой сборки.

## Для чего этот репозиторий

| Задача | Что даёт исходное дерево |
| --- | --- |
| Разработка панели | Встроенная статическая веб-панель и локальный HTTP/API-слой. |
| Работа с runtime | UE4SS Lua-мост и исходники необязательных C++-модулей. |
| Автоматические модули | Безопасный контракт работы только с реально вошедшим игроком. |
| Сборка и проверка | Повторяемые инструкции CMake/MSVC, проверки панели и public-tree gate. |
| Совместная разработка | DCO, шаблоны issues/PR, policy безопасности и контроль изменений форков. |

Это **исходный код для разработчиков**, а не архив с готовым чужим сервером.
В нём нет рабочих адресов, ключей, журналов, данных игроков, баз данных,
резервных копий, игровых файлов, UE4SS-бинарников или непроверенных сторонних
ассетов.

## Как устроено

```text
локальный браузер
      │
      ▼
встроенная веб-панель ──► version.dll: HTTP/API ──► UE4SS bridge ──► SCUM
                                      │                    │
                                      └── проверенные       └── строгий
                                          модульные маршруты    GameThread путь
```

| Каталог | Назначение |
| --- | --- |
| [`src/native`](src/native) | Исходники нативного `version.dll`, HTTP/API и bridge-клиента. |
| [`src/ue4ss_cppmods`](src/ue4ss_cppmods) | Полные исходники C++-модулей UE4SS. |
| [`ue4ss/Mods/ScumNeDjinBridge`](ue4ss/Mods/ScumNeDjinBridge) | Серверный Lua-мост UE4SS. |
| [`ue4ss/ScumNeDjin`](ue4ss/ScumNeDjin) | Безопасные конфигурационные шаблоны и статическая панель. |
| [`docs`](docs) | Ограничения runtime, сборка C++-модулей и инженерные правила. |

Публичный API намеренно не является произвольной серверной консолью. Игровые
операции должны проходить только через ограниченные и проверяемые маршруты.
Внутренний server-command fallback выключен по умолчанию и не является
отдельной публичной точкой управления.

## Быстрый старт для разработчика

1. Прочитайте [границу публичной поставки](PUBLIC_BOUNDARY.md) и
   [правила ассетов](ASSET_POLICY.md).
2. Соберите нативную часть и выполните тесты по [BUILDING.md](BUILDING.md).
3. Если нужны C++-модули, соберите их против **своей** совместимой x64
   `UE4SS.lib` по [инструкции UE4SS C++](docs/UE4SS_CPPMOD_BUILDING.md).
4. Проверьте панель и public-tree gate до любого распространения.

Используйте только собственные конфиги и данные, на распространение которых
есть права. Нельзя добавлять в Git секреты, рабочие snapshots, дампы,
игровые каталоги или сборочные результаты.

## Автоматизация, которая видит реального игрока

Панельная строка, логин в логе и объект игрока в runtime — не одно и то же.
Для автоматических модулей ScumNeDjin использует ограниченный путь:

```text
подтверждённый логин → задержка стабилизации → один cache seed на GameThread
                    → GameState.PlayerArray → cache → модульная очередь
```

Глобальные обходы объектов и постоянные runtime-сканы не являются заменой
этого контракта. Полные инварианты, требования к журналированию и правила
проверки описаны в [PLAYER_AUTOMATION_SAFETY.md](docs/PLAYER_AUTOMATION_SAFETY.md).

## Участие, форки и связь с оригинальным проектом

1. Сделайте fork канонического репозитория и создайте узкую ветку.
2. Добавьте проверку, описание видимого поведения и `Signed-off-by` в каждый
   commit.
3. Откройте pull request в канонический проект.

Подробности — в [CONTRIBUTING.md](CONTRIBUTING.md), [DCO.md](DCO.md) и
[GOVERNANCE.md](GOVERNANCE.md). Для форка или изменённой публичной сборки
обязательны корректное упоминание исходного проекта и ссылка на него; правила
имени и обозначения `Official` зафиксированы в
[TRADEMARK_POLICY.md](TRADEMARK_POLICY.md).
